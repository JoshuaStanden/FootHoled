# H0.1 Pin Map — Waveshare ESP32-S3-Touch-LCD-3.5 (NON-B)

> **This repo targets the NON-B board.** Display controller **ST7796** over
> standard SPI; touch controller **FT6336** over I2C. The LCD/touch reset lines
> (and likely the backlight enable) are driven through a **TCA9554 I2C I/O
> expander**, not direct ESP32 GPIOs. This is the single biggest structural
> difference from the 3.5B.

**Verification status.** The display SPI pins, backlight, and shared I2C pins are
now **verified** from the vendor demo (`08_gfx_helloworld.ino`) and the official
expansion-header pinout. What remains `unverified` is narrower: the exact TCA9554
expander address and its individual bit assignments (touch reset, PWR button
EXIO), the FT6336 INT pin, and the SD-card GPIOs — these live in the schematic /
ESP-IDF factory demo. The display and touch bring-up no longer depends on any
unverified value. Mark anything confirmed on hardware **[HW verified]**.

## Display — ST7796 standard SPI (SPI2 host) — **[verified from vendor Arduino example]**

Source: `ESP32-S3-Touch-LCD-3.5-Demo/Arduino/examples/08_gfx_helloworld.ino`
(`Arduino_ESP32SPI(DC=3, CS=-1, SCK=5, MOSI=1, MISO=2)` →
`Arduino_ST7796(bus, RST=-1, rotation=0, IPS=true, 320, 480)`).

| Signal    | GPIO | Status         | Notes                               |
|-----------|------|----------------|-------------------------------------|
| SCLK      | 5    | **[verified]** | SPI clock                           |
| MOSI (SDA)| 1    | **[verified]** | SPI data to panel                   |
| MISO      | 2    | **[verified]** | Used by the GFX SPI bus             |
| CS        | -1   | **[verified]** | Not a dedicated GPIO (CS=-1)        |
| DC (RS)   | 3    | **[verified]** | Data/command select                 |
| RST       | -1   | **[verified]** | No dedicated reset GPIO; ST7796 inits without it |
| BL        | 6    | **[verified]** | Backlight — direct GPIO (`#define GFX_BL 6`), driven as LEDC PWM |

Pixel clock: **80 MHz** (vendor value) · Resolution: 320 × 480 · Colour: RGB565 · IPS=true (inversion on)

> The vendor path (both the Arduino GFX example and the ESP-IDF factory port)
> drives the panel with **no TCA9554 involvement** — CS/RST are -1 and backlight
> is a plain GPIO. `board_adapter.cpp` matches this exactly: it sets
> `esp_lcd_panel_invert_color(..., true)` and BGR element order, and uses no
> expander for display or touch.

## Touch — FT6336 capacitive (I2C), standard FT6x36 register protocol

| Signal | GPIO         | Status          | Notes                                   |
|--------|--------------|-----------------|-----------------------------------------|
| SDA    | 8            | **[verified]**  | Shared I2C0 bus — pin 28 on expansion header (official pinout) |
| SCL    | 7            | **[verified]**  | Shared I2C0 bus — pin 26 on expansion header (official pinout) |
| INT    | -1 (NC)      | **[verified]**  | Not wired — polled in firmware (vendor uses NC) |
| RST    | -1 (NC)      | **[verified]**  | Not wired — ST7796/FT6336 init without it (vendor uses NC) |

I2C address: `0x38` (FT6336 fixed) · Bus speed: 400 kHz

Touch read (standard FT6x36): write start register `0x02` (TD_STATUS), read 5
bytes `[TD_STATUS, P1_XH, P1_XL, P1_YH, P1_YL]`.
`points = TD_STATUS & 0x0F`; `x = ((P1_XH & 0x0F) << 8) | P1_XL`;
`y = ((P1_YH & 0x0F) << 8) | P1_YL`.
**This is a plain register read — NOT the AXS15231B 11-byte command protocol.**

## I/O expander — TCA9554 (I2C) — **not used by this firmware**

The vendor's own ESP-IDF factory port (`esp_3inch5_lcd_port.cpp`) and Arduino
example bring up both the ST7796 display and the FT6336 touch with **no TCA9554
involvement** (CS/RST/TP_RST/TP_INT are all `GPIO_NUM_NC`). A TCA9554 does exist
on the board and the factory demo uses it for the PWR-button EXIO and some
peripheral control, but it is **not required for display or touch**, so
`board_adapter.cpp` does not touch it. If a future feature needs it (e.g. the
PWR button), its address (0x20–0x27 range) and bit map must be read from the
schematic / factory demo first — those remain `unverified`.

## I2C0 Bus (shared — SDA GPIO 8, SCL GPIO 7) **[verified from official pinout header]**

| Device   | I2C Address | Component                               |
|----------|-------------|-----------------------------------------|
| FT6336   | 0x38        | Touch controller                        |
| TCA9554  | 0x20 (?)    | I/O expander (reset/backlight lines)    |
| QMI8658  | 0x6A / 0x6B | 6-axis IMU (accel + gyro)               |
| PCF85063 | 0x51        | RTC                                     |
| AXP2101  | 0x34        | PMIC (power management)                 |
| ES8311   | 0x18        | Audio codec                             |

> All devices share I2C0. The ESP-IDF new I2C master driver handles concurrent
> access when the bus handle is shared.

## UART / expansion header — **[verified from official 2.54mm pinout header]**

| Signal | GPIO | Header pin | Notes                        |
|--------|------|-----------|------------------------------|
| RXD    | 44   | 25        | UART RX — GNSS candidate     |
| TXD    | 43   | 27        | UART TX — GNSS candidate     |
| BOOT   | 0    | 20        | Strapping / download mode    |

Other GPIOs broken out on the header (available for the FootHoled expansion
connector): 21, 38, 39, 40, 41, 42, 46, 47, 48 (left side); 9, 10, 11, 17, 18,
19, 20 (right side). DN=GPIO19 / DP=GPIO20 are the USB D-/D+ pins.

> **The ST7796 display pins (SCLK/MOSI/DC/CS/backlight) are NOT on this header** —
> the LCD is wired internally and not broken out. Those GPIOs, the TCA9554 bit
> assignments, and the FT6336 INT/RST pins must still come from the schematic or
> `ESP32-S3-Touch-LCD-3.5-Demo.zip`. They remain `unverified` above.
